# SOC Investigation Notes

## Windows Discovery Detection Lab

### Investigation Objective

The objective of this investigation was to validate custom Wazuh detection rules for Windows discovery activity and analyze the Sysmon telemetry generated by each process.

The lab used a Windows 11 endpoint monitored by Sysmon and the Wazuh Agent. Sysmon Event ID 1 (Process Creation) provided process-level telemetry that was forwarded to the Wazuh Manager for detection and investigation.

---

## Detection Summary

| Rule ID | Command | MITRE ATT&CK | Technique |
|---|---|---|---|
| 100100 | whoami.exe | T1033 | System Owner/User Discovery |
| 100101 | ipconfig.exe | T1016 | System Network Configuration Discovery |
| 100102 | systeminfo.exe | T1082 | System Information Discovery |
| 100103 | hostname.exe | T1082 | System Information Discovery |
| 100104 | tasklist.exe | T1057 | Process Discovery |
| 100105 | netstat.exe | T1049 | System Network Connections Discovery |
| 100106 | Multiple discovery events | Behavioral Correlation | Multiple discovery commands within 120 seconds |

---

## Alert Investigation

### 1. User Discovery — whoami.exe

**Rule ID:** 100100  
**Severity:** Level 6  
**MITRE ATT&CK:** T1033 — System Owner/User Discovery  
**Telemetry:** Sysmon Event ID 1

The `whoami.exe` process was detected on the Windows endpoint. The event showed that the command was launched from PowerShell and executed with Medium integrity.

**Analyst Assessment:**  
The command identifies the current user. It is commonly used by administrators and normal users, but it may also appear during discovery activity. In this controlled lab, the activity was expected and classified as benign.

**Verdict:** Expected / Benign Lab Activity

---

### 2. Network Configuration Discovery — ipconfig.exe

**Rule ID:** 100101  
**Severity:** Level 5  
**MITRE ATT&CK:** T1016 — System Network Configuration Discovery  
**Telemetry:** Sysmon Event ID 1

The detection captured `ipconfig.exe` execution from PowerShell. This utility can reveal network interface configuration and other host networking information.

**Analyst Assessment:**  
`ipconfig` is a legitimate Windows utility and frequently appears during troubleshooting. Its security significance depends on surrounding activity and process context.

**Verdict:** Expected / Benign Lab Activity

---

### 3. System Information Discovery — systeminfo.exe

**Rule ID:** 100102  
**Severity:** Level 5  
**MITRE ATT&CK:** T1082 — System Information Discovery  
**Telemetry:** Sysmon Event ID 1

The `systeminfo.exe` process was detected from the same PowerShell session. This utility provides information about the operating system and host configuration.

**Analyst Assessment:**  
The command is legitimate but can provide useful host information during discovery. Context and surrounding activity should be reviewed before determining whether execution is suspicious.

**Verdict:** Expected / Benign Lab Activity

---

### 4. System Name Discovery — hostname.exe

**Rule ID:** 100103  
**Severity:** Level 5  
**MITRE ATT&CK:** T1082 — System Information Discovery  
**Telemetry:** Sysmon Event ID 1

The `hostname.exe` utility was detected executing from PowerShell. It returned the system's computer name.

**Analyst Assessment:**  
Hostname discovery alone is low-confidence activity. When combined with additional discovery commands in a short period, it can provide stronger behavioral context.

**Verdict:** Expected / Benign Lab Activity

---

### 5. Process Discovery — tasklist.exe

**Rule ID:** 100104  
**Severity:** Level 5  
**MITRE ATT&CK:** T1057 — Process Discovery  
**Telemetry:** Sysmon Event ID 1

The `tasklist.exe` utility was detected from PowerShell. It enumerates processes running on the Windows system.

**Analyst Assessment:**  
Process enumeration is commonly performed for legitimate administration and troubleshooting. It can also be relevant during security investigations when observed alongside other discovery behavior.

**Verdict:** Expected / Benign Lab Activity

---

### 6. Network Connection Discovery — netstat.exe

**Rule ID:** 100105  
**Severity:** Level 5  
**MITRE ATT&CK:** T1049 — System Network Connections Discovery  
**Telemetry:** Sysmon Event ID 1

The `netstat.exe` process was detected from PowerShell. The event provided process creation information associated with network connection discovery activity.

**Analyst Assessment:**  
`netstat` is a legitimate troubleshooting utility. Execution becomes more interesting when correlated with other discovery activity from the same endpoint or process context.

**Verdict:** Expected / Benign Lab Activity

## Behavioral Correlation

Individual discovery commands can generate false positives because they are also used during legitimate administration.

To improve detection context, Rule `100106` was created to correlate repeated discovery detections occurring within a short period.

**Correlation Configuration:**

- Rule ID: `100106`
- Severity: Level 8
- Frequency: 3
- Timeframe: 120 seconds
- Matched Group: `discovery_command`
- Alert Group: `discovery_correlation`

During testing, Wazuh successfully generated the Level 8 correlation alert.

The correlation alert was associated with an `ipconfig.exe` event, while preceding discovery activity was retained in the event context. This demonstrated that the correlation alert should be interpreted as a behavioral detection rather than as a synthetic event containing every individual discovery command as separate fields.

---

## Process Context

During investigation, multiple discovery processes were observed originating from the same PowerShell session.

This provided additional context beyond the individual detection rules and demonstrated the importance of reviewing:

- Parent process
- Command line
- Process ID
- Process GUID
- User
- Integrity level
- Event timestamp
- Related activity

Multiple related discovery events can be more significant than a single isolated command.

---

## False Positive Analysis

The monitored utilities are legitimate Windows tools and should not automatically be treated as malicious.

Examples of legitimate use include:

- System administration
- Network troubleshooting
- IT support
- Inventory collection
- Diagnostic activity

For this reason, the individual detections were assigned moderate severity levels while the behavioral correlation rule was assigned a higher severity.

A SOC analyst should review process context, user activity, timing, parent process, and surrounding security events before escalating an alert.

---

## Investigation Conclusion

All six custom discovery rules successfully detected their intended Windows processes through Sysmon Event ID 1 telemetry.

The behavioral correlation rule also successfully generated a higher-severity alert when repeated discovery activity occurred within the configured time window.

The investigation demonstrated an end-to-end detection workflow:

**Windows Process Execution → Sysmon → Wazuh Agent → Wazuh Manager → Custom Detection → MITRE ATT&CK Mapping → Alert Investigation → Behavioral Correlation**

The test activity was intentionally generated in the controlled lab environment and was classified as expected/benign.

The project demonstrates the importance of combining atomic detections with contextual analysis and behavioral correlation rather than treating every individual command execution as malicious.
